## Scientific direction

The useful contribution is a controlled study of source-dependent transfer
through separately trained connectors. Keeping the backbones fixed makes
connector interventions interpretable. The S1 separation of correct-image
utility, correct-minus-shuffled grounding, and correct-minus-grey sensitivity
is appropriate. So are matched replay controls, image-level pairing, and the
explicit single-seed limitation of Block C under Option 1.

The architecture alone is not a sufficient novelty claim. X-LLM already
describes interfaces aligning multiple frozen encoders with a frozen LLM;
LangBridge establishes the text-bridge lineage. The revised question is
better positioned than the superseded claim of solving xGQA's original call.
Primary sources checked:
[X-LLM](https://arxiv.org/abs/2305.04160),
[LangBridge](https://arxiv.org/abs/2401.10695), and
[SigLIP 2](https://arxiv.org/abs/2502.14786).

Block B can localize functional differences in recombined checkpoints. Block
C can estimate the effect of freezing a connector under its matched recipe.
Even a positive C2 result would not uniquely establish that loss of FLORES
directional alignment mediates the effect: freezing also preserves scale,
boundary embeddings, the gate, and other features. Keep the preservation
mechanism as a hypothesis. A failed Bengali G0 is also a result about that
checkpoint on that panel, not proof that no source or architecture can ground.

## Findings requiring action

1. **P1 — Block D destroys pairing in its bootstrap.**
   `analysis/block_d.py:118–134` draws independently for each donor because
   the RNG key includes `s`. S1 requires one draw per target/subset shared by
   all donors. The input schema has no subset or question identifiers and
   does not enforce matching image universes. In a synthetic example with
   seven identical donors, 40 images with alternating binary outcomes, seed
   0 and 400 resamples, point regret is zero but its upper bound is **25
   points**; a paired bootstrap must give exactly zero throughout. An image
   universe mismatch is accepted. Implement joint draws, subset strata,
   item identities and validation before using these intervals.

2. **P1 — Undefined correlations become significant evidence.**
   `analysis/block_d.py:64–74` compares permutations to a NaN correlation
   when either rank vector is constant. Every comparison is false, so it
   returns `p = 0`. With identical constant positive donor outcomes, all
   three currently implemented verdict flags pass. A constant damage vector
   also returns zero. Return an explicit undefined/inconclusive result or
   abort; reject non-finite inputs and test both constant-vector cases.

3. **P1 — The implemented D-donor verdict omits a required guardrail.**
   `analysis/block_d.py:135–145` accepts one endpoint and reports three
   conditions. S1 requires a fourth: the utility-regret upper bound. It also
   defines the selected donor's pooled grounding under the general item-micro
   rule; the code instead averages target means. Macro weighting is explicitly
   allowed for alpha, which should remain macro, but the pooled guardrail
   needs its own weighting. Without both endpoints the code cannot issue a
   complete G3 decision. The production adapter from alignment files and
   correct/shuffled per-item results is also absent; the CLI only accepts
   `--from-json` with precomputed damage and cells.

4. **P2 — The power artifact does not preserve xGQA translations jointly.**
   `analysis/power_sim.py:84–98, 142–149` treats bn/de/ko as independent
   strata, both for the perturbation and bootstrap. The artifact consequently
   lists 1,194 images, although there are 398 unique images translated into
   three languages. This violates S1's shared-image resampling rule. Recompute
   the power artifact with joint image draws and sign flips; do not infer
   that its current numerical power conclusions necessarily reverse.
   Separately, the document calls simulated negative effects
   reference-minus-candidate while `_boot.region` interprets negative values
   as candidate worse. Unify this sign convention. MGSM/MSVAMP power is not
   implemented, and the G3 power grid tests only the correlation criterion,
   not the conjunction including regret and utility. Label these limits.

5. **P1 before GPU submission — S1 evaluation and branch loading are pending.**
   The current evaluators expose neither the complete A-arm controls nor
   shuffle maps. `model.py:205–206` rejects both branches disabled, and
   `model.py:347–352` cannot build a prompt-only prefix. Missing/corrupt
   images are skipped in current evaluators, allowing different item sets
   between image conditions. `common.py:203–225` loads every available
   branch with `strict=False`: a second joint checkpoint overwrites both
   branches, and a pre-gate checkpoint loaded into a reused module inherits
   its previous gate. These limitations are acknowledged in DESIGN; they
   must become implemented properties. There is no `eval_matrix.py`, shuffle
   generator, S1 manifest/submit guard, or `analysis/block_a.py` at this HEAD.
   Build the per-block analysis along with the evaluator, not after harvesting.

6. **P1 before chained training — A checkpoint is mistaken for completion.**
   `job-scripts/train_stage3_all.sh:92–95` skips a run whenever the best
   mapping checkpoint exists. `train_stage3_vqa.py:411–415` writes that
   checkpoint after the first improving epoch. A two-epoch job interrupted
   during epoch two will therefore be skipped as done on resubmission.
   Separate best-checkpoint existence from an atomic completion marker that
   validates the intended configuration and completed training budget.
   The existing resume path also reconstructs a shuffled loader and skips
   batches without restoring its original permutation. Periodic snapshots
   can occur inside gradient accumulation (defaults: save every 200 batches,
   accumulate 16), but snapshots omit pending gradients. S1's deterministic
   sampler must be complemented by saves at optimizer boundaries or exact
   gradient/accumulation restoration. Verify interrupted versus uninterrupted
   training before relying on 12-hour chaining.

7. **P2 — Current scope and operational documentation disagree.**
   `Approach2/README.md:76–82` still recommends LoRA as the next mitigation,
   contrary to S1's frozen-backbone scope. It also attributes LoRA to
   MERLIN stage 2, whereas local `MERLIN/train_merlin.py:293,337–342`
   enables it in the reasoning stage and freezes the mapping there.
   The root README leads to Approach 1. Update the entry points to identify
   the active recipe, S1 status and legacy launchers. Preserve historical
   decisions in DESIGN but eliminate contradictions inside the current S1:
   Block A specifies **96** CVQA invocations while its ledger lists **72**;
   confirmatory donor estimates of 35/51 hours coexist with the measured
   **19.341 GPU-hours**; C5 replication is both mandatory conditionally and
   future work under Option 1; extra stability seeds are both listed in scope
   and conditional. Specify the Option 1 override, and define what
   “promising” means for the optional confirmatory donor launch. No pinned
   dependency/environment file was found in M2-ALIGN; capture the validated
   cluster environment and model/tokenizer revisions for reproducibility.

The already documented Block C corrections remain necessary: frozen towers
must stay in evaluation mode, the train/validation split must be by image,
and C5 needs a genuinely absent text branch through tokenization, loading,
training and evaluation. The single-seed pilot does not validate a general
freeze-text method or a preservation loss.

1. Correct Block D, its adversarial tests, power pairing/signs, and the
   inconsistent current specification. Keep the existing scientific question.
2. Freeze the corrected specification with complete pre-freeze artifacts.
   The recorded data audit passed; this is not a request to redo it.
3. Implement S1 evaluators, strict branch loading, deterministic shuffle maps,
   manifests, completion checks and submit guards. Capture the environment.
4. Verify full prediction parity for legacy bn/bn and id/id cells, branch
   absence, prompt-only generation, identical item universes, and replay of
   the same shuffled maps. Finish Block A analysis before its submission.
5. Run A and apply its fixed decision rules. Then run B and the C pilot as
   authorized by the gate; D remains a separate exploratory contribution.
   If optional C5 replication is deferred under Option 1, leave G1-T unresolved.
6. Keep R0/R1 and the preservation loss as future work. Apply a concrete,
   predeclared contingency to the roughly 19.3-hour donor confirmation panel;
   additional historical-checkpoint seeds estimate stability, not a new method.
